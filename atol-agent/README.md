# Фискальный агент АТОЛ

Маленькое Node.js-приложение, которое ставится на любой ПК/мини-ПК **в той же
локальной сети**, что и касса АТОЛ (не обязательно на том же компьютере, что
и планшет с терминалом — достаточно общей сети). Оно:

1. Опрашивает backend (`GET /api/fiscal/jobs/next`) — есть ли новое задание
   (открыть/закрыть смену, пробить чек) для заведения, к которому привязан
   агент по токену.
2. Выполняет задание на кассе через официальный драйвер АТОЛ (пакет
   [`node-atol-wrapper`](https://github.com/farafonov-alexey/node-atol-wrapper),
   уже содержит нужные бинарники — отдельно "Драйвер ККТ 10" с сайта АТОЛ
   ставить не нужно).
3. Отправляет результат обратно на backend (`POST /api/fiscal/jobs/:id/result`).

Backend никогда не обращается к кассе напрямую — она не в его сети. Вся связь
идёт наружу от агента к backend (агент сам стучится в интернет, а не наоборот),
поэтому никаких открытых портов/форвардингов на роутере точки настраивать не
требуется.

## Установка

Нужен Node.js 18+ (для встроенного `fetch`).

```bash
cd atol-agent
npm install
cp .env.example .env
```

Заполните `.env`:

- `BACKEND_URL` — адрес вашего backend (например `https://imperial-mc.online`).
- `AGENT_TOKEN` — берётся в бэкофисе: **Заведения → нужное заведение → «Касса
  АТОЛ» → «Создать токен»**.
- `KKT_IP` / `KKT_PORT` — IP кассы в локальной сети точки и порт канала обмена
  (обычно 5555, если не меняли — смотрите в настройках самой кассы или в
  QuickResto → Оборудование → АТОЛ, где сейчас настроен IP/порт).
- `KKT_MODEL` — числовой код модели. Известные модели:
  - АТОЛ 11Ф — `67`
  - АТОЛ 25Ф — `57`
  - АТОЛ 30Ф — `61`
  - Полный список смотрите в `node_modules/node-atol-wrapper/bindings.d.ts` →
    `enum Model`, если модель другая.

## Известный нюанс на Linux: служба UEM

Свежие версии драйвера ДТО10 на Linux требуют работающей фоновой службы
`uem-agent` (это не про фискализацию, а внутренняя телеметрия/лицензии АТОЛ)
— без неё `open()` падает с ошибкой `11 [Для работы с драйвером необходимо
запустить службу UEMA]`. Проще всего это обойти, создав пустой файл — драйвер
проверяет его наличие и если он есть, не требует запущенной службы:

```bash
mkdir -p ~/.atol/drivers10
touch ~/.atol/drivers10/uem.env
```

Сделайте это один раз на машине с агентом. Проверено на этой версии пакета:
после создания файла ошибка 11 уходит, и вместо неё при недоступной кассе
корректно возвращается ошибка `2 [Нет связи]` — то есть дальше остаётся только
реальная связь с кассой, а не служебная лицензионная проверка.

## Запуск

```bash
npm start
```

В логе будет видно каждое обработанное задание и «сырой» ответ кассы —
это нужно на первом этапе, чтобы свериться с реальным форматом ответа
драйвера (номер фискального документа, ФПД и т.д. — см. `TODO` в
`src/index.js`, поля вычленяются по предварительным названиям, которые
могут отличаться на вашей версии драйвера).

Рекомендуется запускать через `pm2`/systemd/NSSM (на Windows), чтобы агент
поднимался автоматически после перезагрузки ПК.

## Формат заданий (JSON-задания ДТО10)

Задания строит backend (`backoffice/src/services/fiscalQueue.js`) —
`openShift`, `closeShift`, `sell` (продажа). Систему налогообложения и ставку
НДС мы не передаём — они настроены по умолчанию на самой кассе, как раньше в
QuickResto. Перед боевым использованием на новой точке имеет смысл сверить
точный формат полей через утилиту «Тест драйвера ККТ» → «Работа с JSON»,
подключившись к реальной кассе — так проще увидеть, какие поля она ожидает и
что возвращает при успехе (для сопоставления в `extractFiscalInfo` в
`src/index.js`).
